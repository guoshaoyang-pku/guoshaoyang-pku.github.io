这份文档回答三个问题：每个 MLS-Bench 任务到底在做什么（背景、输入、输出、怎么打分）、 deepseek-v4-pro 模型在任务中实际做了什么（它写的算法、它改了哪些东西）、 以及 中间到底发生了什么（模型观察了什么中间量、怎么调试、怎么迭代）。

01 causal-observational-linear-gaussian

任务背景：因果发现是什么

因果发现（causal discovery）的目标是：只凭一堆观测数据，反推出变量之间的因果结构——也就是"谁直接导致谁"的有向图。 举例：我们观测到"喝咖啡的人心脏病发病率高"。但可能是咖啡导致心脏病（A→B），也可能是心脏病让人多喝咖啡（B→A）， 还可能是有第三个因素（比如压力大）同时导致两者（A←C→B）。因果发现就是从数据里区分这三种可能。

本任务的假设是 线性高斯结构方程模型（linear Gaussian SEM）：每个变量的值 = 父变量的线性组合 + 高斯噪声。 在这个假设下，因果结构有一个著名的不可识别性结论：仅凭观测分布，你最多只能识别到 CPDAG（部分有向无环图）——即哪些边存在、哪些方向确定、哪些方向未定。 但是！如果所有变量的噪声方差相等，结构就完全可识别（可以区分所有方向）。这是本任务的核心知识点。

模型做了什么（EVS 算法）

agent 写了一个全新的算法 EVS（Equal-variance Cholesky Score search，等方差 Cholesky 分数搜索），核心思路：

  1. 顺序搜索：利用等方差结构（协方差逆矩阵 = (I−B)ᵀ(I−B)/σ²），用"叶剥离"（每次剥掉一个最像叶子的节点）恢复拓扑顺序；再用一个平滑的联合似然分数做细化。
  2. 创新点：bagged 共识顺序。在弱边上，单个样本的分数几乎平坦、容易猜反方向。agent 用 bootstrap 重采样 + 多数投票（Copeland 计分）把这种随机噪声平均掉。只有当细化顺序的优势「显著」（bootstrap 校准的 2 个标准差检验）时才采用细化结果，否则用集成顺序。
  3. 创新点：联合边集坐标下降。因为共享方差把所有节点耦合在一起，逐节点贪心会丢掉被相关父节点掩盖的弱边；所以改为对整组边做 add/remove/swap 的坐标下降。
  4. 稳定性选择的边池（Meinshausen & Bühlmann 2010）：48 次子采样拟合中，边必须被选中超过 1/3 次才保留（真实边都 ≥17/48，伪边都 ≤16/48，无需每数据集调参）。

02 causal-observational-linear-non-gaussian（LiNGAM）

任务背景

上一个任务（linear-gaussian）里我们说过：线性高斯模型下，如果噪声方差不等，因果方向不可识别（只能到 CPDAG）。 本任务打破了「高斯」这个假设——变量之间的机制仍是线性的，但噪声可以是非高斯的（比如均匀分布、t 分布等）。

LiNGAM（Linear Non-Gaussian Acyclic Model，线性非高斯无环模型，Shimizu et al. 2006）发现了一个漂亮的定理： 在线性 + 非高斯噪声的假设下，因果方向是完全可识别的，甚至可以恢复完整 DAG（不只是 CPDAG）。 直觉是这样：如果 X → Y（Y = aX + ε，ε 非高斯），那么「对 X 回归 Y 的残差」和「X」是独立的； 反之如果方向反了，「对 Y 回归 X 的残差」和「Y」会相关。利用独立性的不对称性就能定方向。

这个任务给 3 个场景：ER30、ER50（随机有向图，30/50 个节点）和 SF100（无标度图，100 节点）， 官方 baseline（DirectLiNGAM、ICALiNGAM）在部分场景会有 2–6 条伪边。

模型做了什么（Pruned DirectLiNGAM）

agent 实现的是 Pruned DirectLiNGAM——官方 DirectLiNGAM 的顺序搜索 + 一个统计剪枝的回归阶段：

  1. 因果顺序：标准的 DirectLiNGAM 迭代找 sink 节点（用 dMI 统计量度量非高斯独立性），向量化实现。
  2. 父节点集：每个变量对它在顺序中的前驱做 adaptive Lasso（BIC 选惩罚）。

03 causal-observational-nonlinear（非线性加性噪声因果发现）

任务背景

前两个任务都是「线性」机制。本任务把机制换成非线性：每个变量的值 = 父变量的非线性函数 + 加性噪声。 这是更接近真实世界的设定（比如基因调控、气候变量之间通常不是简单的线性关系）。

非线性带来了新的可识别性：加性噪声模型（ANM, Additive Noise Model）定理说明，在大多数非线性情况下， 因果方向是唯一可识别的。核心观察是：如果 X → Y（Y = f(X) + ε，ε 与 X 独立）， 那么残差 Y − f(X) 与 X 独立；但反过来 X = g(Y) + ε' 的残差通常与 Y 不独立。 这种「方向不对称性」就是识别因果方向的钥匙。本任务即要求实现这样一个非线性因果发现算法。

05 causal-treatment-effect（因果处理效应估计）

任务背景

这是因果推断里的「黄金问题」：估计处理效应（treatment effect）。 场景是：有一群人，一部分接受了某种处理（吃药、广告、政策），另一部分没有。我们想回答： 「如果给每一个人都施加处理，效果会怎样？」——这叫个体处理效应（ITE）， 以及「平均下来效果多大？」——这叫平均处理效应（ATE）。

难点在于反事实缺失：一个人要么被处理、要么没被处理，我们永远看不到「如果他走了另一条路会怎样」。 所以必须用统计方法（倾向性得分、双重稳健估计、元学习器等）来抵消选择偏差。 本任务用 3 个合成数据集：IHDP（母婴健康干预，经典基准）、Jobs（工作培训计划）、ACIC（大样本）。 每个数据集同时报 PEHE（个体效应估计误差）和 ATE error（平均效应误差）。

模型做了什么（VARDR-X）

  1. 异方差感知的正交权重：最终 CATE 回归用 w = (T−e)²/√σ̂²(X)，其中 σ̂²(X) 是交叉拟合的条件方差模型。

  3. 倾向性分层 winsorization：对伪结果的尾部按倾向性分层层截断（尾部集中在极端倾向层）。
  4. 集成：正则化 HistGBM + RF + Robinson 残差校正成员 + X-learner 成员 + 线性自适应多项式岭锚点。
  5. 鲁棒 ATE 校准：集成均值锚定到 AIPW 和 Robinson ATE 的逆方差混合（两者偏置模式相反）。

06 ml-symbolic-regression（符号回归）

任务背景

符号回归（Symbolic Regression）的目标是：给定一组 (输入, 输出) 数据点，找到一个数学表达式（而不是一个黑盒神经网络）来解释它们。 比如给你一堆 (x₀, x₁, y) 的数据，你要发现 y = 2·sin(x₀)·cos(x₁) 这个公式。 它和「曲线拟合」的区别在于：输出是可读的公式，而不是一堆权重。

主流的求解工具是遗传编程（Genetic Programming, GP）：维护一群表达式（程序树），通过「变异/交叉」演化、 「适应度」选择，逐渐逼近正确答案。本任务用 3 个经典基准：nguyen7（单变量外推）、nguyen10（双变量周期函数）、 koza3（经典 Koza 基准）。评测指标是测试集 R²。

任务内容与评测

项说明
输入3 个基准的数据点（训练/测试划分）：nguyen7、nguyen10、koza3
agent 可改文件gplearn/custom_sr.py（gplearn 库的可编辑部分）
评测指标每个基准的测试 R²，任务分 = 几何平均
官方 baseline标准 GP、带简洁性压力的 GP、ε-lexicase GP（0.9977/0.8836/0.9855 等）

模型做了什么（Memetic ε-Lexicase GP）

agent 在 gplearn 里实现了一个混合 GP 搜索策略：

  1. 适应度塑造：归一化 MSE + 线性简洁性压力 + 平滑性正则化（拒绝高频插值——那些在训练点上穿行、但在留出点上震荡的坏表达式）。
  2. 选择：混合 ε-lexicase / 锦标赛。Lexicase 用 MAD 半动态 epsilon 对每个样本的误差做逐样本比较；锦标赛用带简洁惩罚的适应度。可退火混合。
  3. 算子：六种结构化变异（子树/点/常数扰动/常数插入/提升/折叠）+ 轻度代数化简 + 深度检查的交叉。
  4. Memetic 步：线性缩放修复嵌入树中 + 坐标下降常数爬山 + scipy 非线性最小二乘常数拟合（对结构有希望的精英）。
  5. 多样性维护：自适应算子率（适应度多样性崩溃时提高变异率）+ 每代 ~8% 随机移民。

07 ml-anomaly-detection（异常检测）

任务背景

异常检测（Anomaly Detection）的目标：从一堆数据里找出「不正常的点」——比如信用卡欺诈、网络入侵、传感器故障。 难点是异常点极其稀少（可能只占 1–30%），而且我们通常没有标签（无法监督学习）， 只能靠「正常数据长什么样」来推断哪些点偏离了正常模式。

本任务用 ADBench 的 4 个标准数据集：cardio（心脏病监测，异常 9.6%）、thyroid（甲状腺，2.5%）、 satellite（卫星影像，31.6%——异常占比非常高，极难）、shuttle（航天飞机，7.2%）。 评测用 AUROC 和 F1（在最优阈值下）。官方 baseline：Isolation Forest、One-Class SVM、ECOD、COPOD、LOF 等。

模型做了什么（CRC：Contamination-robust Consensus scoring）

agent 实现了一个全新的异常打分器 CRC（Contamination-robust Consensus scoring，抗污染共识打分）：

  1. RGM：稳健高斯模型。用迭代重加权最小二乘（Huber 风格软截断）重估位置/散布，让异常点被降权而不是污染正常模型。
  2. cHRGM：约束稳健高斯混合。自动决定混合分量数（权重必须都超过下限，拒绝吸收异常簇的伪小分量），每个分量用同样的重加权最小二乘。这让密度视图在 ~30% 污染（Satellite）下依然可靠。
  3. 自适应排序聚合：8 个视图（IForest、PCA、ECOD、OCSVM、RGM | HBOS、cHRGM、KDE）各自打排序分，统一化后做「精度共识 P」和「密度共识 D」（幂均值 p=3）的软 max 混合（temperature 10）——让最强的共识在它对的地方主导，同时不让单一噪声视图赢。

08 ml-clustering-algorithm（聚类）

任务背景

聚类（Clustering）的目标：给一堆没有标签的点分组，让「组内的点相似、组间的点不同」。 这是最基础的无监督学习问题——客户分群、图像分割、文档归类都用它。

本任务有 3 个数据集，难度差异很大：blobs（球形簇，简单）、moons（两个月牙形，非凸——K-Means 会失败）、 digits（手写数字 64 维，高维流形）。评测指标：ARI（聚类与真实类别匹配度）、NMI（互信息）、 Silhouette（轮廓系数）。官方 baseline 就是 K-Means（ARI 0.935/0.481/0.534）。

任务内容与评测

项说明
输入3 个数据集：blobs（1500 点 2 维）、moons（1000 点 2 维）、digits（1797 点 64 维）

模型做了什么（MUSES：Multi-Scale Spectral Ensemble）

agent 实现了一个三阶段算法 MUSES（Multi-Scale Spectral Ensemble with Consensus Refinement，多尺度谱聚类集成 + 共识精修）：

  1. 多尺度谱视图：在 kNN 高斯亲和图上跑归一化谱聚类，多个尺度（高维 d>10 用 {3,5,10}，低维用 {7,8,10}），自适应选择。
  2. 标签空间证据累积：对多个尺度的分区做匈牙利对齐的逐元素多数投票（O(m·n·k) 共识，对谱聚类对图尺度的敏感性鲁棒；≥3 个视图保证真有大多数）。
  3. 邻域共识精修：标签传播去噪——把每个点重新指派到其 kNN（k=5）的大多数标签，清除孤立误分（ARI/NMI 最惩罚这种）。

09 ml-dimensionality-reduction（降维）

任务背景

降维（Dimensionality Reduction）的目标：把高维数据（比如 28×28 像素的手写数字 = 784 维）压缩到 2–3 维， 同时尽量保留数据结构，让人类可以可视化、或者让后续算法更快。最著名的工具是 t-SNE 和 UMAP。

本任务 3 个数据集：MNIST（手写数字 784 维）、Fashion-MNIST（服装图片 784 维）、newsgroups（新闻文本 50 维）。 评测指标是降维后邻居保持质量：kNN accuracy（降维后分类准不准）、trustworthiness（可信度——降维后成为邻居的点在原空间是否也近）、 continuity（连续性——原空间邻居在降维后是否还近）。官方 baseline 是 t-SNE。

任务内容与评测

项说明
输入3 个高维数据集（784/784/50 维 → 降到低维）
agent 可改文件scikit-learn/bench/custom_dimred.py

官方 baselinet-SNE（MNIST knn 0.868 / trust 0.963 / cont 0.966）

模型做了什么（APNE：Adaptive-Perplexity Neighborhood Embedding）

agent 实现了一个新的非线性嵌入算法 APNE：

  1. 维度自适应 perplexity：对称高斯亲和力，高维输入（像素，d≥100）perplexity=20，低维（newsgroups，d=50）perplexity=30。更紧的局部模型让 k=7 邻域（评测所量的）保持锐利。
  2. 稀疏精确吸引 + 周期精确排斥：吸引是每个点 top-60 亲和力上的精确计算；t-SNE 的全体对 (1+d²)⁻² 排斥（带配分函数 Z）每 8 次迭代重算一次（「排斥外推」：场是 1/d⁴ 衰减的对项之和，平滑，旧刷新只是微小误差；把 O(n²) 排斥成本砍 8 倍同时保持精确梯度质量）。
  3. 优化器：每坐标增益 + 动量、early exaggeration (α=12)、自动学习率 max(n/48, 50)、PCA 初始化。
  4. 环境修复：把 20newsgroups pickle 回填到固定的 SKLEARN_DATA_HOME，让 newsgroups 评测离线可跑。

agent 还试过「持久非归一化排斥地板 + 约束弹簧」（crowding 修复），但实验显示它会牺牲 trustworthiness（产生簇尾），所以被移除——这是「试了 → 观察到副作用 → 否决」的典型路径。

10 ml-calibration（概率校准）

任务背景

概率校准（Calibration）解决一个很实际的问题：模型说「我有 90% 的把握」，它真的 90% 时候是对的吗？ 很多模型（尤其深度网络）会过度自信——它对很确定，但实际错的概率更高。校准就是把模型输出的置信度 调整到「和真实正确率一致」。

本任务 4 个场景：rf-mnist（随机森林+手写数字）、mlp-fashion_mnist（神经网络+服装）、 gbm-madelon（梯度提升+高维）、svm-breast_cancer（SVM+小样本乳腺癌，只有 ~110 校准样本）。 评测指标：ECE（期望校准误差，越低越好）、Brier 分数、NLL（负对数似然）。 官方 baseline：temperature scaling、Platt、isotonic 回归等。

模型做了什么（ASMC：Adaptive Smooth Monotone Calibration）

15 ml-missing-data-imputation（缺失值填补）

任务背景

真实数据几乎总有缺失值（问卷没答、传感器没记录、数据库丢行）。直接扔掉缺失样本会浪费数据甚至引入偏差。 缺失值填补（Imputation）就是用统计方法把缺失的地方「猜」出来，让下游模型能用完整数据。

本任务 3 个数据集：breast_cancer、wine、california_housing。评测两个层面： RMSE（填补值与真实值差多少，越低越好）和 downstream（填补后下游分类/回归的效果，越高越好）。 官方 baseline：MICE（链式方程）、GAIN（生成对抗填补）、mean/median 等。

任务内容与评测

项说明

模型做了什么（DSEI：Damped Stacked-Ensemble Chained Imputation）

agent 实现了一个新的填补算法 DSEI（阻尼堆叠集成链式填补 + 低秩热启动）：

  1. 低秩热启动：截断 SVD 矩阵补全（soft-impute 风格）初始化链式方程循环，而不是用列均值——在拟合任何回归之前先利用全局跨特征相关。
  2. 堆叠逐列预测器：每列用 ridge + extra-trees + kNN 集成，权重每轮从观测条目重估（内部划分的逆方差 + 竞争选择，丢掉明显输家）。
  3. 不确定性门控的阻尼更新：每轮只往集成预测走一部分（收缩动量），树集成分歧大的条目步长更小——防止早期轮次的振荡和误差累积。
  4. 样本量自适应组合：小数据集（每模型质量估计噪声大）保持多样混合（5% 多样性下限）；大数据集每列锐化为最佳模型（比值 1.10）。
  5. 缺失感知的列排序 + 最终全替换轮。

16 进展图与时间线：怎么读

下面的内容解释结果报告里那些「进展图 / 时间线」到底画了什么、每一根线是什么意思、以及每个任务中间发生了什么。 我们刻意用最直白的方式讲，不堆术语。

16.1 一张「评测进展图」是怎么来的

每个 agent 会话，我们记录了它的每一次工具调用（读文件、改代码、跑命令、跑评测），带时间戳。 把这些调用按时间画出来，就得到「进展图」——它本质上是一张「agent 在任务里干了什么」的时间线。

在一张典型的进展图上，你会看到：

  • 横轴：时间（从 agent 启动到结束）。
  • 不同的色块/点：不同类型的动作——读文件、改代码、跑命令、跑评测。
  • 稀疏段：agent 在思考/等命令输出（比如训练跑很久）。
  • 密集段：agent 在快速迭代（读→改→测循环）。

16.2 每种动作代表「中间发生了什么」

动作在图上的样子它代表 agent 在做什么
读文件稀疏的紫色点agent 在理解任务说明、现有代码、评测脚本——这是「侦察」阶段。
写脚本（probe/debug）连续绿色点agent 在写小实验验证某个中间量（数据对不对、算法某个环节是不是瓶颈）——这是「局部观察」。
跑 bash黄色点agent 在运行实验、查看输出、下载数据。密集的黄色往往意味着它在一个问题上反复试。
改代码绿色点agent 根据观察修改主算法——这是「intervention」。
跑评测红色点（往往间隔很大）agent 跑一次完整的官方评测，拿最终指标。红点之间的间隔就是「一次评测的耗时」。
长时间无动作空白段评测在后台跑（比如 2 小时的训练），agent 在等结果。

16.3 从图里能读出什么结论

1. 「观察-干预」循环的密度：一个任务里，如果「写 probe 脚本 → 看输出 → 改代码」的循环出现很多次， 说明这个任务确实是「需要 debug/构造」的类型——agent 在靠中间观察推进，而不是一次梭哈。 我们在 ai4sci-mol（20+ probe）、nonlinear（39 debug 脚本）、discrete（8 debug 脚本）上看到的正是这种密度。
2. 评测红点的稀疏程度：红点很稀（比如 treatment-effect 只有 3-4 个）说明评测很贵，agent 被评测成本限制了迭代。 红点很密（比如 calibration）说明评测便宜，agent 可以大量快速迭代。
3. 开始段的「侦察」长度：agent 花多少时间读任务/摸环境，能反映任务的新颖度。 ai4sci-mol 一开始花了很久摸环境（装包、下权重、对齐数据管线），因为它是个全新的、依赖外部包的 setting。
