# KB setting

新异步实验使用以下设置；具体 release、输入哈希和模型配置随 run 保存。

| 项目 | 设置 |
|---|---|
| 题目 | release v3 共 980 题：arch80、ranking v2 400、v3 300、dataflip200；固定 seed 抽样，dataflip 整对保留，共享实例整组划分，已知旧曝光组仅进 train。 |
| 计分 | 选择题 1/0；排序逆序对 0/1/2/3 得 1/0.75/0.5/0.25，其余 0。引用 claim 记 s+=score、f+=1−score；这是使用反馈。 |
| 解题与总结 | gpt-6.1-sol / Codex；本次 Opus 工具链未通过实时验证，使用 sol 的变更明确写入配置。每题同时做无 KB 对照。 |
| KB 与 batch | 默认完整短 KB，按需一次展开多条 claim 或 science；本次计划 15 轮，每轮 30 题，回答与揭示答案之间保存冻结版本。 |
| 持久任务 | 总结者与研究者独立进程；40 分钟后原任务继续并标发起轮次，4 个 worker 保留总结容量；研究工具调用不限 14 次。 |
| 恢复与 commit | 原会话和 checkpoint 恢复；修改提案由主进程原子应用；commit 记录发起、应用轮次和研究 repo 版本。 |
| Science | 持续更新的研究报告，可覆盖多条 claim，保留竞争解释、预测、证据和未决问题；最新已保存版本下轮即可读取，无 ready 门槛。 |
| 评测 | 每 5 轮在 105 题 ranking v2/v3 val 上每组重复 3 次；连续两个下降超过 1 SE 的检查点才回滚，非显著性检验。arch/dataflip 因旧曝光缺少新 holdout；最终 test 关闭。 |
| 公网 | 沿用实验 viewer 展示完整 KB、报告、代码与日志；内容变化后每 30 分钟发布并核验线上字节。 |
