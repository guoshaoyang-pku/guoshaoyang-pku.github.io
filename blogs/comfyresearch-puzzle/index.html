把训练曲线变成一道可判分的题

ComfyResearch 的 Puzzle 不是一张“看起来像 M 形”的截图，而是一条可编辑的训练图、一个明确的现象 contract，以及一个会对真实 Trainer 历史返回 PASS / FAIL / WAITING / INVALID 的 verifier。本页从隐藏入口 puzzle1 出发，展示具体的两峰等高题。

1. 从“随机图”到“可验证谜题”

Lottery 的原始体验是：输入数字或句子，画布生成一条 Dataset → Model → Optimizer/Loss → Trainer 工作流。Puzzle 在这个入口上增加了研究问题：同一张图不仅能被再次拿到，还要说明“要观察什么、哪些条件固定、怎样算答对、结果不能说明什么”。

phenomenon要观察的训练动力学，例如 M-shaped test loss 的两个局部峰。
settings固定 graph、dataset、model 和指定随机源，记录可改变的控制变量。
result从 Trainer 的数值历史计算峰位置、峰高和检查项，而不是读图猜形状。
boundary明确区分 smoke、候选、full evidence 与跨 seed 的稳定性结论。
核心原则：曲线是线索，verifier 才是接口。一个截图可以帮助人发现现象，却不能替代有限值检查、峰检测和明确的布尔判断。

2. 隐藏入口：输入 puzzle1

在当前个人分支的实现中，Lottery 输入框有一个不出现在公开 Templates library 里的入口：输入 puzzle1（大小写和首尾空白均不敏感），画布会载入完整的 M-shape puzzle graph。普通数字 1 仍然是随机 seed=1，不会被彩蛋劫持。

9 nodesDataset、Model、SOAP、Loss、Observable、Trainer、Training Viz、Weight L2 Viz 与 Puzzle completion。
8 edges完整保留训练链路；最关键的是 Trainer.loss_results → Puzzle completion.results。
可编辑这不是只读 demo。用户可以修改参数、替换 subquestion、运行 Trainer，或复制 verifier 到自己的 graph。
输入 puzzle1
  → resolveHiddenLotteryTemplate
  → Dataset / Model / SOAP / Loss / Trainer
  → Trainer.loss_results
  → puzzle_completion.results
  → 峰检测与 checks
  → WAITING / FAIL / PASS / INVALID

隐藏的是题目的交付入口，不是答案。

路由只负责交付一个可复用的 GraphDocument；它不保存运行时曲线、plot 或 checkpoint，也不在输入阶段“生成一个答案”。答案由 graph 里的 verifier 根据当前 Trainer 历史重新计算。

3. Verifier：答案不是截图

puzzle_completion 是一个面向训练结果的分析节点。它从上游 Trainer 的 testLossHistory 和 stepTicks 读取数据，先做输入完整性检查，再检测局部峰，最后执行某个已注册 subquestion 的 contract。

状态何时返回含义
WAITING训练尚未产生足够的曲线点题目还不能判分，不是失败。
INVALID长度不一致，或历史中出现 NaN / Inf输入证据不满足 verifier 的数据契约。
FAIL曲线有限且已找到峰，但 checks 未满足当前实验没有答对这道题。
PASS所有必要 checks 均满足当前 graph 与当前训练历史满足题目条件。

m_second_peak_larger 的最小 contract

  • stepTicks 与 testLossHistory 长度一致且全为 finite；
  • 按时间排序，用 prominence ≥ 0.5、最小峰间距 20 检测局部峰；
  • 至少找到两个峰，并判断 secondPeakHeight > firstPeakHeight。
用户侧最小构造：在画布中放置 Puzzle completion，把 Trainer 的 loss_results 连到它的 results 输入，再选择已有 subquestion。新增一条全新的 Python/JS 判定规则，则需要扩展代码、schema、UI 和测试。

4. 具体 Puzzle：m_equal_peaks 两峰等高

这次展示的具体题目把问题从“第二峰是否更高”改成更窄、也更容易审计的目标：M-shaped test-loss 的前两个 qualified peaks 高度差是否不超过 10%。

Graph / Dataset固定 graph；dataset seed=8221uniform_linear_motion_dataset，其余核心数据结构保持不变。
Modelmodel seed=7814gated_mlp_model；固定模型结构与参数初始化。
OptimizerSOAP；optimizer seed=957beta1=0.9、beta2=0.95、epsilon=1e-8、weight decay=0、preconditionFrequency=10、maxPreconditionerDim=1024。
控制变量learning rate=1.6e-4只在允许范围内调整 lr；旧的 1.7e-4 候选在当前引擎上已不再复现。
Trainer3000 steps；log every 10；train seed=50000；minibatch seed=60000full batch、test evaluation at log ticks、CPU；这些 seed 用于 full evidence 的确定性 contract。
目标m_equal_peaks前两个 qualified test-loss peaks 的相对高度差 ≤ 10%。
Peak 18.5185 @ step 1130
Peak 28.7899 @ step 1950
Relative gap3.09% ≤ 10%
判定PASS
为什么不是 1.7e-4？旧候选来自较早的捕获环境；在当前 engine、且其他 seed 固定时，它给出约 10.61 / 2.60 的两峰高度，约 75% 差异，因此是 FAIL。这个例子说明 puzzle 的关键不是保存一个漂亮的旧截图，而是让候选在当前实现上重新通过 verifier。

下面的图来自 M-shape full-run evidence。上排是 test-loss；下排是同一 run 的 global Weight L2 observable。左侧为两峰等高候选，右侧保留一个“第二峰更高”的对照候选，用来说明两个 subquestion 关注的是同一类曲线上的不同数值关系。

证据纪律：route smoke 只验证 puzzle1 能解析为 9-node/8-edge 图、普通 1 不被劫持、每次加载返回独立副本；它不等于 Trainer full run，也不等于 evaluator PASS。完整结果还应保留 graph、config、curves、observables、checkpoint 与 status。

6. 和远程 main / server 的关系

核对时，远程 main 已支持“把一个 GraphDocument 注册到某个 Lottery seed 并再次导入”的能力，但它和当前 puzzle1 的关键字直达不是同一套实现。

维度当前 puzzle1远程 Lottery registry
触发方式输入特殊文本 puzzle1，做 NFKC、trim、lowercase 后精确匹配注册的 uint32 seed；英文句子先经 FNV-1a hash 再查 registry
存储前端 registry 内置 GraphDocumentlottery_seed_registry.json 与 graph-library API
路由命中后直接替换当前画布命中后把固定图放入 matrix cell，未命中仍走随机生成器
ID 处理返回固定 document 的深拷贝导入时重映射节点、边和 parent/child 引用
判题能力图中显式带有 puzzle_completion 与 wiringregistry 本身只保证图可重复出现，不自动推断 phenomenon、运行 Trainer 或证明 PASS

所以“应该是路由到一个隐藏 template”这个判断，对 puzzle1 是准确的；对远程 main，更准确的说法是“路由到公开 Templates library 之外的固定 GraphDocument registry”。两者产品语义相同：把一个可重复的惊喜图交付给用户；差异在于入口、存储和 ID remap。核对基线的远程 generated NodeKind/spec 还没有本地 puzzle_completion，不能把远程 seed registry 直接写成完整 Puzzle 系统。

7. 结果边界：目前能说什么，不能说什么

  • 能说：在固定 graph、dataset/model/optimizer/train/minibatch seeds 和当前 engine 下，lr=1.6e-4 产生了两个高度相近的 qualified peaks，relative gap=3.09%，通过 m_equal_peaks。
  • 能说：verifier 将曲线输入、峰检测、阈值和状态输出显式化，用户可以在画布里修改 graph 后重新判分。
  • 不能说：这个 PASS 证明了跨 seed、跨机器、跨 optimizer 或跨版本的普遍规律。
  • 不能说：隐藏 route 的 3/3 smoke 证明了科学现象；smoke 只证明题目 graph 能被正确送达。
  • 仍开放：更复杂的 Slingshot / staircase puzzle 需要分别定义稳定的 qualified spike、恢复与平台斜率 contract，不能因为 M-shape 成功就一并宣称解决。
一句话总结：隐藏种子负责“把题目送到画布”，Trainer 负责“产生证据”，Puzzle completion 负责“按 contract 判分”；三者分开，Puzzle 才能复现、审计和扩展。
