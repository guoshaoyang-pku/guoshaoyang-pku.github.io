M 与 L 的含义

M = Mathematical milestone：M0 到 M8 是数学主干里程碑，描述从工具链、流形几何、热核与抛物分析、DeTurck 短时流，到熵/约化体积、κ-非塌缩、canonical neighborhoods、手术灭绝和最终拓扑识别的依赖链。

L = Lifecycle / control layer：L0 到 L3 是 swarm 控制生命周期层：L0 人类 PI/主控，L1 数学组长，L2 独立 executor 进程，L3 verifier/证据层。L 编号表示控制职责，不代表数学难度。

进度条：百分比表示证据和工程闭合度估计，不是已证明定理百分比。block 只有在构造输入、编译、下游 checked use、独立 rebuild、axiom audit 和语义审查全部完成后才算关闭。

三层控制架构

L0 · 人类 PI / 主控

冻结数学边界、证据等级、全局 DAG、资源策略和 publication branch；不把 worker 数量当进度。

L1 · 数学组长

L1 Lean baseline、L2 upstream、L3 analytic、L4 geometric、L5 topology/audit。每组维护局部 DAG、checkpoint 和 child-task outbox。

L2 · executor fleet

每个 task 使用独立 worktree 和独立进程组，bounded invocation、heartbeat、result card；dispatcher 是唯一派发入口。

L3 · verifier / evidence

记录 source hash、build log、per-file Lean check、forbidden-token scan、#print axioms、semantic class 和 downstream use。

生命周期纪律

  • 上级停止任务先写 TERMINATE_REQUESTED，再 kill 该任务进程组。
  • dispatcher 识别终止标记后置为 stopped，不会自动 requeue。
  • transport failure 只触发重试/恢复，不改写数学状态。
  • 唯一 integrator 才能合并 publication branch。

可展开工程 DAG 与验收门

控制面 → 执行面

queue schema → dependency admission → 独立 worktree → worker process group → checkpoint/heartbeat → result card。

验收：schema-valid task、依赖满足、heartbeat 新鲜、日志和 artifact 可定位。

执行面 → 证据面

result card → compile gate → axiom/declaration audit → semantic review → downstream consumer → promotion。

验收：不得用 TASK_DONE 掩盖 gate failure、模型结果或未完成审计。

恢复 DAG

SSH/relay 失败 → 保留 state/worktree → bounded retry → 从 checkpoint 恢复 → 重新验证 source hash。

验收：不删除现场，不重复计算已完成结果。

发布 DAG

worker branch → integrator batch → clean build → audit snapshot → publication branch → blog deployment。

验收：高频 push 只推送已审阅的控制面和证据，不把未跟踪实验文件混入。

时间窗合理目标不能据此声称
未来 24 小时更多真实 child admission；M0–M5 的局部编译 artifact、反例、适配和条件接口。不能声称任何完整 Perelman 层级已经关闭。
数天到一周若 leader 递归持续健康，可形成一批可复现局部 lemma、上游兼容矩阵和审计账本。不能把 queued/verified 数量线性换算成证明百分比。
数周到数月可能完成若干关键接口的真实 downstream consumer，并减少部分具名 blocker。不能跳过 M3–M7 的串行分析、几何和奇点输入。
完整主干仍按多月到多年规划，取决于非平凡数学投入和独立 kernel/axiom/semantic audit。当前数据不支持“几天完成完整 Ricci flow”。
