3.3 机制解释：选项代码本身泄露了任务类型

  • 选项侧的生成代码足以判断 family：CE loss + 2 logits = 二分类、reshape(-1, vocab) = bigram LM、输入维度 = tabular 类型。
  • 知道 family + setting（优化器/lr/架构/预算）后，剩下的全靠「选项侧先验」排序——数据集卡片写的是哪个实例几乎不影响判断。

4. 这对 benchmark 设计意味着什么

核心问题：当前题目区分的是「选项侧启发式先验」的好坏，而不是「分析这个具体数据集」的能力。数据集卡片写了等于没写。
  • v1.6 改进方向（刘子鸣提出）：选题时筛选数据集敏感题——同一个选项集合，换同 bucket 的另一个数据集实例后 GT 赢家会翻转的题。出题器可以在同一 candidate set 跨数据集复用候选来发现这种翻转对，逼着答题者必须读数据集。
  • GT 裁决实验（进行中，不调 API 跑真实 GT）：把 20 对配对题的候选代码（3 choice × 10 seeds × 20 对 = 120 个 GT 作业）拿到对方数据集上真实重训。两种结果指向不同结论——
    • GT 赢家换数据集后很少翻转 → 模型忽略数据集是理性的，"数据集没用"是出题性质，不是模型缺陷；
    • GT 赢家经常翻转但模型答案不动 → 模型真的在偷懒，数据集推理是未开发的区分度来源。
  • 信息剂量分层实验（进行中）：盲测 → 现有卡片 → +完整 synthesize.py → +家族采样器源码（uni/mv sampler 168/236 行、bigram 生成器、tabular 规则库 582 行），配 GT 翻转率，画完整的「信息量 → 正确率」分层图。

5. 对明天考试（9/5 18:00-21:00，50 题）的策略含义

既然「分数主要由选项侧先验决定」，那么选项侧判据就是主要得分来源——这正是刘老师规则库 + KB v2 + 我们 GT 实测覆盖的内容。考前优先级：
  1. optimizer_only 题（约 1/3）按流程走，这是最稳的分：先排 SGD+tiny lr → Adam/AdamW/RMSProp 同级比 lr（甜区 1e-3~3e-3）→ AdaGrad 按 η_eff≈η/√t 换算（短预算要放大名义 lr）→ wd/loss/layer_norm 直接忽略。
  2. architecture_only 题（约 1/3）是拉开差距的地方，且要预期反直觉答案：LLM 在这类题只有 37-61%（子集上甚至低于随机），因为「更深/更宽/更多稳定器 = 更好」的先验在短预算 GT 下经常是错的。GT 实测要点：depth=1 必欠拟合；depth≥3 / width≥256 在噪声大/高维实例上惨败（d2w64 赢 d4w256）；bigram 选 GRU 不选 transformer，transformer 内部加深无益、d_ff 64→256 有帮助。
  3. 混合题按「优化器 → 有效 lr → 架构」的顺序做 successive elimination（刘老师决策链），dominant effect 出现就停。
  4. 数据集卡片还是要读，但只读关键字段：input_dim（≥8 → 别选大模型）、noise_std（0.1 → 容量收敛）、rule_family（spiral 多圈 → 深度不可替代；xor → 一隐层够）、vocab_size（算 ln V 基线）。
  5. 预算题：16k/32k 大预算占一半，长预算下小 lr 能追平高 lr、AdaGrad 后期衰减，套用短预算结论前先换算训练步数（steps = budget / batch_size）。
  6. 人类 vs LLM 的机会窗口：LLM 天花板目前 ≈0.77-0.81，arch 题是它们最弱的地方（<50%）。人只要 arch 题正确率过 60%，总分就能进前列。
