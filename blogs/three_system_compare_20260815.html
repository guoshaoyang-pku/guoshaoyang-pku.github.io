01 总结论与核心发现

三系统定位

维度interactive（官方）codexdsh（deepseek-harness）
任务覆盖全部全部全部
深研能力浅（20 steps 预算内）最深（可无限探索）深（2h 预算内自主迭代）
限流韧性强（内置重试）弱（断连即死，需手动接管）强（内置 rate-limit 重试）
自动结算无（需手动）无（需手动）有（dsh_budgeted.sh 自动评测+记录）
成功率中低（限流断连）高
核心发现：dsh 的闭环机制（2h 预算 + 自动最终评测）让它成为最高效的批量生产系统； codex 探索最深但没有预算/自动结算，限流断连需要外部手动接管，且可能产出计算开销过大的实现。

每个系统一句话

dsh —— 批量生产主力
  • 2h 预算 + 自动最终评测 + 自动记录，零人工干预
  • 14 任务 12 成功（2 评测失败），成功率最高
  • 在 causal 任务上产出 PERFECT 结果（SHD=0）
  • 内置 rate-limit 重试，限流下韧性最强
codex —— 单点最强但不可靠
  • 可无限探索/调试，产出最深的方法（本地 F1 0.925 nonlinear）
  • 无预算控制、无自动结算，限流断连即死需手动接管写回
  • 可能产出计算开销过大的实现（GBR-peel 评测 1h48m 未完成一个 case）
  • 4 任务 2 次需手动接管

03 指标字典：每个任务的指标是什么意思

怎么读这张表：MLS-Bench 每个任务有若干 评测场景（Label），每个场景测一组 指标。 分数表里的缩写（如 SHD、F1、ECE）都是领域专业术语，下面按任务逐一解释它们的含义与"越大越好 / 越小越好"。

通用指标（多个因果任务共用）

缩写全称含义方向
SHDStructural Hamming Distance 你恢复的因果图与真实图之间不一致的边数（漏掉 + 多出 + 方向错的边都算）。0 = 完美还原。 ↓ 越小越好
F1F1 score 边预测的精确率与召回率的调和平均。要求骨架和方向都正确才算对。1.0 = 完美。 ↑ 越大越好
Precision / Recall精确率 / 召回率 精确率 = 你预测的边里多少是真的；召回率 = 真实存在的边里你找回了多少。 ↑ 越大越好
Adj Precision / Recall邻接（骨架）精确率/召回率 只看有没有边（不管方向）的精确率/召回率。 ↑ 越大越好
Arrow Precision / Recall箭头（方向）精确率/召回率 只看边方向是否正确的精确率/召回率。 ↑ 越大越好

3.0 各任务评测场景 = 什么数据

任务评测场景（Label）每个场景测什么
causal-observational-linear-gaussian
线性高斯因果发现		 ER10 / ER20 Erdos-Renyi 随机图，10/20 个节点。ER20 更稠密、更难。
SF50 / SF50-HardScale-Free（无标度）图，50 节点。Hard 版更稠密（m=3）且样本更少。
ER20-NoisyER20 + 更高噪声（噪声方差 2.5），样本更少（400），隐藏场景（agent 看不到分数）。
指标：SHD、Adj Precision/Recall、Arrow Precision/Recall（见上表）。
看点 线性高斯下观测数据只能识别到 CPDAG（等价类）， SHD=0 意味着完全还原了真实等价类——dsh_b5 在全部 4 个场景都做到。
causal-observational-linear-non-gaussian
线性非高斯因果发现（LiNGAM）		 ER30 / ER50 Erdos-Renyi 图，30/50 节点。
SF100Scale-Free 图，100 节点（最大），隐藏场景。
指标：F1（主）、SHD、Precision、Recall。
看点 非高斯噪声让因果方向完全可识别（超越等价类）。 dsh 的 SAIL-LiNGAM 和 NG-SCREEN 都做到 F1=1.0 / SHD=0（完美）。
causal-observational-nonlinear
非线性因果发现（加性噪声模型）		 SF20-GP Scale-Free 图 20 节点，高斯过程非线性，指数噪声。
ER20-GaussER 图 20 节点，混合非线性，高斯噪声。
ER12-LowSampleER 图 12 节点，只有 150 个样本（极少），隐藏场景。
看点 这是 5 个因果任务里最难的一个（非线性 + 多样性）。 最好的 dsh_b4 达到 F1≈0.94（SF20-GP）；低样本场景 F1≈0.86。
causal-discovery-discrete
离散因果发现（贝叶斯网络）		 Cancer / Child / Alarm 经典小规模贝叶斯网络（5/20/37 个变量），结构已知的真实网络。
Hailfinder / Win95pts大规模真实网络（56/76 变量），Win95pts 是隐藏场景。
指标：SHD（越小越好）。
看点 恢复真实离散贝叶斯网络的结构。dsh 在小网络上 SHD≤5，但大网络（Hailfinder/Win95pts）还有很大差距（SHD 28-76）。
ml-anomaly-detection
无监督异常检测		 cardio / thyroid / satellite / shuttle 4 个真实异常检测数据集（心脏病/甲状腺/卫星/航天飞机传感器）。
指标：AUROC（异常判定曲线下面积）、F1（异常点检出 F1）。都是越高越好。
dsh 结果 gmean≈0.93，超越 baseline Isolation Forest 的 0.782。
ml-calibration
概率校准		 rf-mnist / mlp-fmnist / gbm-madelon / svm-breast 4 个"模型+数据集"组合：随机森林 MNIST、MLP Fashion-MNIST、GBM Madelon、SVM 乳腺癌。
指标：ECE（期望校准误差，越小越好）、Brier score（越小越好）、NLL（负对数似然，越小越好）。
dsh 结果 最佳 ECE 0.0065（rf-mnist），全面优于早期版本。
ml-clustering-algorithm
聚类算法		 blobs / moons / digits 3 个聚类数据集：高斯团、两月牙（非线性可分）、手写数字。
指标：ARI（调整兰德指数，越高越好）、NMI（归一化互信息，越高越好）、Silhouette（轮廓系数，越高越好）。
dsh 结果 DASCC 在 moons 上 ARI=1.0（完美），远超 k-means 的 0.48。
ml-dimensionality-reduction
降维		 mnist / fashion-mnist / newsgroups 3 个数据集降到低维嵌入。
指标：kNN 准确率（降维后 kNN 分类，越高越好）、Trustworthiness（可信度）、Continuity（连续性）。
看点 mnist knn_acc 0.859 是评测修复后补录的。
ml-subgroup-calibration-shift
子群校准（分布偏移）		 adult / compas / law_school 3 个真实数据集，关注最差子群（如按种族/性别分组的少数群）的校准。
指标：worst_group_ece（最差子群 ECE，越小越好）、Brier、subgroup_auroc、max_subgroup_gap（子群间最大差距，越小越好）。
dsh 结果 SCC 算法最差子群 ECE 比 baseline 好 2.9-3.3×。
ml-selective-deferral
选择性延迟（置信度拒绝）		 adult / compas / law_school 模型可以选择"不预测"（延迟），目标是延迟后保留样本的错误率要低。
指标：selective_risk_at80（覆盖 80% 样本时的错误率，越小越好）、coverage_at80（越接近 0.8 越好）、worst_group_selective_risk（最差子群错误率）、deferral_rate_gap（延迟率差距）、AUROC。
看点 adult risk@80 0.074，完整分数已记录。

为什么有些场景是 hidden（隐藏）：MLS-Bench 会运行 hidden 评测场景但不把分数反馈给 agent（如 ER20-Noisy、SF100、ER12-LowSample、Win95pts）。 这防止 agent 在可见场景上过拟合，衡量方法的真实泛化能力。所以分数表里 hidden 场景的数字尤其能说明问题。

06 GPU / 时长分析

重要限制：两机 8 张卡被多系统共享，nvidia-smi 监控无法精确归因到单个系统 （三系统 monitor 记录的活跃 GPU 时长几乎相同 ≈19.7 GPU-hours，都是整机 GPU 占用）。 这些任务大部分是 CPU-bound 的（causal / ML 任务几乎不占 GPU），所以 wall time 是更可靠的对比指标。

07 关键经验

  1. dsh 需要 DSH_PERMISSION_MODE=danger-full-access 才能执行 shell（否则 sandbox 拒绝所有 shell 命令）。
  2. codex 无预算控制：会无限探索/调试，限流断连即死，需要外部手动接管写回。
  3. codex / dsh 都是"深研型"：先在 /tmp 本地开发（dev_harness、variants、multiseed），最后写回 workspace 的 custom_algorithm.py / custom_cate.py。
  4. codex 可能产出计算开销过大的实现（GBR-peel 评测 1h48m 未完成一个 case），不适合评测。
  5. sklearn 类任务的 dsh_budgeted 默认 PY（mlsbench env）缺 sklearn，需用 mlsbench-scikit-learn env 重跑最终评测。
  6. API 限流显著：8–9 并发 agent 时 codex 频繁断连；dsh 内置重试韧性更好。
