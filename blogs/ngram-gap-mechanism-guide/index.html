N-gram Gap 机制指南

本文档解释 n-gram gap 实验中的核心概念：什么是 table、gate、shell、optimizer grouping，它们如何组合产生 train/val gap，以及关键实验数据。目标读者是刚接手项目的研究者。

1. 什么是 n-gram table

n-gram table 就是一张巨大的查表（lookup table），和 token embedding 没有本质区别。区别在于：token embedding 用 token id 做 key，n-gram table 用几个连续 token 组成的 context 做 key。

table 的规模

table 类型context行数每行维度hash 方式
unigram单个 token32,768768直接用 token id
bigram前一个 + 当前 token2,097,152 (32K × 64)64 × 2 = 128乘法 XOR hash
trigram前两个 + 当前 token2,097,15264 × 2 = 128乘法 XOR hash
fourgram前三个 + 当前 token2,097,15264 × 2 = 128乘法 XOR hash

bigram/trigram/fourgram 的行数都是 vocab_size × 64 = 32768 × 64 = 2,097,152。hash 把 n 个 token 映射到这个范围内的一个整数。每层用不同的 hash prime，使不同层的同一 context 映射到不同行。

为什么不用直接查表？ 因为 bigram 的可能组合有 32768² ≈ 10 亿种，trigram 有 32768³ ≈ 3.5 万亿种。直接建表不现实。hash 到 2M 行会产生 collision（不同 context 映射到同一行），但 collision 率很低（batch 内 bigram ~20%，trigram ~8%），而且每层用不同 prime + K=2 双 hash 进一步降低有效 collision。

2. Hash 机制详解

hash 的作用是把 n 个 token id 压缩成一个 row 号。具体实现是乘法 + XOR + 取模，全部在 GPU 上以 tensor 整数运算完成。

train.py:1536-1546 — hash 计算
# 输入: prev_idx, prev2_idx 是 shifted token id tensor [batch, seq_len] # idx 是当前 token id tensor [batch, seq_len] # Bigram: 两个 token → 一个 row row = ((prev_idx * p1) ^ (idx * p2)) % 2_097_152 # Trigram: 三个 token → 一个 row row = ((prev2_idx * lp[0]) ^ (prev_idx * lp[1]) ^ (idx * lp[2])) % 2_097_152

每层使用不同的 prime 组（来自 MurmurHash/FNV/golden-ratio 家族），保证不同层的同一 context 映射到完全不同的行。K=2 multi-hash 是指每个 n-gram 查两次独立 hash，各取半个维度（64 维），拼成完整的 128 维。

3. Gate 机制：table 如何注入到模型

n-gram table 查出的 value 不会直接加到模型输出上——它经过一个 input-dependent gate 控制注入强度。gate 本身是一个小 linear layer + sigmoid。

train.py:1721-1728 — gate 注入
def _add_value_residual(self, branch, v_heads, residual, gate, x, channel_start, heads): # residual = table 查出的 value [B, T, heads, head_dim] residual = residual.view(x.size(0), x.size(1), heads, self.head_dim) # gate: 从 hidden state 取前 32 维 → linear → sigmoid → ×2 gate_input = x[..., channel_start : channel_start + self.ve_gate_channels] value_gate = 2 * torch.sigmoid(gate(gate_input)) # 范围 [0, 2] # 逐位置乘 gate gated = value_gate.unsqueeze(-1) * residual # 加到 attention value 上 return v_heads + gated

gate 初始化为全 0 权重，所以 2×sigmoid(0) = 1.0——训练初期 gate 全开（中性），之后模型自己学习该在什么时候、什么位置放大或抑制 n-gram value 的注入。

gate 是 gap 的关键放大器。实验数据显示：epoch1 期间 trigram gate_rms 只有 0.088（几乎不工作），但进入 epoch2 中段后 gate_rms 上升到 0.29——gate 被训练起来后，table 中积累的历史内容才被"放大"为可见的 train loss 下降。

4. Shell 是什么：nanoGPT vs current shell

项目中有两类模型架构，称为 "shell"（外壳）。它们的区别在于 transformer block 的内部结构。

nanoGPT shell

经典 nanoGPT 架构。标准 LayerNorm、标准 attention、标准 MLP。

# NanoGPTBlock x = LayerNorm(x) x = x + SelfAttention(x) x = LayerNorm(x) x = x + MLP(x)

即使加 n-gram table + RMSProp + 高 LR，也不产生 gap。

current shell (GPT)

从 current/GPT 架构移植的 block。包含 x0 residual、resid_lambda、split QKV 等额外结构。

# Block (current shell) x = resid_lambda*x + x0_lambda*x0_gate*x0 x = x + SelfAttention_splitQKV(x) x = x + MLP(x) # attention 内部: V += ngram_gate × table_value

n-gram table 注入到 attention value stream 的方式和 nanoGPT shell 不同。在 current shell 下，gap 出现。

关键区别不在 table 本身（两者都可以有相同的 n-gram table），而在于 reader 的传输路径：current shell 的 attention split QKV + 残差路径使 n-gram value 在后层 residual 中被更有效地放大。这是为什么 nanoGPT shell 即使加上所有组件仍然无 gap，而切到 current shell 后 gap 出现。

"current-style n-gram injection" 指的是 n-gram value 被注入到 attention value stream 的具体坐标和方式。nanoGPT-style injection 和 current-style injection 的数学结构不同（注入位置、gate 通道分配、与 attention 的交互方式），这决定了 reader Jacobian Ji,a 的大小。

5. Optimizer grouping：两个独立的概念

项目中 "optimizer" 相关的配置有两个独立维度，经常被混淆。这里明确区分。

维度一：n-gram table 用什么 optimizer

由 nanogpt_ngram_optimizer 控制，决定 table 参数的更新算法：

维度二：参数分组与 LR 分配

由 optimizer_grouping 控制，决定每类参数的学习率：

参数类型nanoGPT-style groupingcurrent-style grouping

关键差异：current-style grouping 给 n-gram table 的 LR 是 0.6，而 nanoGPT-style 只有 0.004——差 150 倍。这个 LR 差异是 gap 出现的必要条件：高 LR 使 table 在 epoch1 内快速积累 train-specific content，到 epoch2 时形成足够强的 history state。

RMSProp 对比 AdamW：为什么对 sparse table 更合适

AdamW（有 first moment）
m = β₁·m + (1-β₁)·grad # momentum v = β₂·v + (1-β₂)·grad² update = lr · m / (√v + ε) # β₁ = 0.8 → 半衰期 ~3 步 # sparse row 隔几十步才被访问 # → m 已衰减到 ~0，等于每次"重启"
RMSProp（无 first moment）
v = β₂·v + (1-β₂)·grad² update = lr · grad / (√v + ε) # β₂ = 0.999 → 半衰期 ~693 步 # ≈ 2 个 epoch 的长度 # → v 能跨 epoch 持久化 # → 写入方向 = 当前梯度，不被稀释

以下因果链基于 20260721-min-bigram-trigram-obth-history10 的 observable 数据。每个环节都有直接测量证据。

高 LR (0.6) + RMSProp (无 momentum 稀释) 使每个被访问的 row 写入纯 train 方向的 gradient。bigram raw_value_rms 从初始增长到 10.4，trigram 到 8.2。但此时 reader gate 还没训练起来 (trigram gate_rms = 0.088)，所以 gap 不可见。
epoch 边界 (step 337/338): row condition 突变
rows_adjacent spike (bigram 0.20→0.81, trigram 0.04→0.69)，写入强度突增 (direct_kernel_advantage writer_batch: high_order 0.047→0.073)。但 Dhist 此时反而下降 (0.545→0.490)，说明边界处没有立即产生 gap。
epoch2 早中段 (step 350-500): reader gate 被激活
trigram gate_rms: 0.088 → 0.29。gated_value_rms: 0.86 → 4.08。gate 的训练使 table 中已积累的历史内容开始被放大为 logits 上的有效 signal。
train 阶梯下降 gap
Dhist train_early (high_order): 0.49 → 1.19。table 中的历史 row 内容在 train probe 上大幅降低 loss。train loss 从 3.32 阶梯下降到 2.64。
val loss 翘起 gap
Dhist val_fixed (trigram): +0.063 → -0.154 (变负!)。table 中的 train-specific row content 被 val 文本访问时，因 residual 方向不对齐而产生 cross-penalty。val loss 从 3.34 反弹到 3.71。
gap 持续扩大 gap
train loss 持续下降，val loss 在 reader 完全建立后趋于稳定。gap 从 0.03 扩大到 1.1+。epoch3 第二次重复时 gap 进一步扩大到 3.5+。

11.9 关键发现：Gate 与 Gap 的时间错位

核心发现

Gate 的学习主要发生在 epoch 1-2（变化率最快），但 gap 在 epoch 3 最显著（gap ~4.0 vs epoch 2 的 ~1.3）。 这意味着 gate 本身不是 epoch-3 gap 爆发的直接原因。 真正的机制是：gate 在 epoch 1-2 建立"注入通道"（gate 从 ~0.1 激活到 ~0.27）， 然后 epoch 3 时 table content 的累积 pattern 通过已经稳定的 gate 被放大， 导致 train loss 继续快速下降而 val loss 停滞/上升。

  2. Epoch 2：Gate 变化率仍快，trigram gate 从 0.067 激活到 0.27（4×跃升）。Table content 增长率达到峰值（0.027/step）。Gated value RMS 从 1.0 飙升到 6.26。Gap 出现（~1.3）——注入通道建立完成。
  3. Epoch 3：Gate 趋于稳定（变化率仅 0.002/step）。但 table content 继续累积（16.97→20.35）。Train loss 继续快速下降到 0.7，val loss 停在 4.7。Gap 爆发到 4.0——gate 已经不再变化，但已经打开的通道让 table 中的 train-specific pattern 持续放大。

这解释了为什么 NGRAM_NORM 实验（给 table 加 RMSNorm）不能消除 gap：即使 table content 被归一化， gate [0,2] × unit_vector 仍然足以放大 train-specific pattern。问题不在于 table 的 scale， 而在于 gate 建立通道后，table 中积累的 pattern 通过通道被持续放大。

14.11 关键发现（修正版）

Hit Count 分析结论 — 之前的"高频 memorize"假设被推翻
  1. Novel context 是 val 翘起的最大单一来源：30% 的 val token 来自 train 中从未出现过的 context， 这些 token 平均 loss ~5，贡献 ~1.5 的总 val loss（占 29.5%）。
  2. Gap 是全局性的，不是高频特有：所有 bucket 的 val-train gap 都在 epoch 2-3 爆发， 且幅度相近（4-5）。
  3. 低频 bucket 反而最容易 memorize：eq1 的 train loss 最低（0.465），val loss 5.315， gap 贡献第二（+0.31）。
  4. 5k+ 高频 bucket 是 QA pattern（`? Answer:` 等），train loss 反而高（0.77）， val loss 反而最低（3.37），对 gap 贡献几乎为 0。
  5. 真正驱动 gap 的是低中频 bucket（6-10、21-50、51-100、101-200）， 合计贡献 ~1.4 的 gap（占 32%）。
  6. Step 750 cliff：所有 bucket 的 train loss 在此同步坍塌，与 LR schedule 切换吻合， 同时 val loss 开始上升——模型在 LR 变小时从"学习通用 pattern"切换到"memorize 特定样本"。
机制解读（修正版）

之前认为"高频 n-gram 被 memorize 导致 val 翘起"是错误的。正确机制是：

  1. 幂律分布的天然后果：71.8% 的 unique context 在 train 中只出现 1 次。 Val 中 30% 的 token 的 context 在 train 中完全不存在（novel）。 这部分 token 的 loss 不可避免地高（~5），贡献 29.5% 的 val loss。
  2. 低中频 bucket 的 memorize：出现 6-200 次的 context，模型在 train 中已经能较好地预测后续 token （train loss ~0.7-0.9），但在 val 中即使遇到相同 context，由于后续 token 不同， 模型的"过度自信"反而出错（val loss ~5）。这是真正的 memorize-overfit 区域。
  3. 高频 bucket 反而不过拟合：5k+ bucket 是 QA pattern， 后续 token 本身就有很强的统计规律（答案通常是简短实体）， 所以 train 和 val 的 loss 都相对低且接近。
  4. LR schedule 的关键作用：step 750 的 train loss cliff 与 LR 切换同步。 在 LR 较大时（epoch 1-2），模型学习的是通用 n-gram pattern，val loss 也下降。 在 LR 变小时（epoch 3），模型开始 memorize 训练集中的特定样本，val loss 上升。

14.12 完整机理：从阶梯下降到 Val 翘起

现在我们可以把整个 gap 现象的因果链完整串起来。整个过程分三个阶段，每个阶段都有不同的主导机制， 而 hit count 分布是理解这一切的钥匙。

起点：训练集的 trigram context 呈典型幂律分布。71.8% 的 unique context 只出现 1 次， 但 50% 的 token 来自 hit count ≥ 7 的 context。这决定了模型在不同频率区间面临完全不同的学习任务。

第一个 epoch：通用 pattern 的快速学习。 在 LR 较大（warmup 后 lrm≈0.33）的阶段，模型对所有频率区间的 token 都在学习"通用 n-gram pattern"。 从图 14.5 看，所有 bucket 的 train loss 都在稳定下降，从初始 ~5 降到 epoch 1 结束时的 ~2.5。 这个阶段 val loss 也在下降，因为通用 pattern 在 train 和 val 上都适用。 图 14.4 显示 epoch 1 结束时 val loss 达到最低点 ~2.4——这是模型的"最佳泛化点"。

Train loss 关键 bucket 演化。注意 epoch 1（step 0-337）所有 bucket 平稳下降， 没有出现频率分化——这是"通用学习"阶段。

第二个 epoch：分化的开始。 从 epoch 2（step 337）开始，不同频率 bucket 的 train loss 出现分化。 低频 bucket（eq1, eq2）继续快速下降，因为样本少，模型很容易把这些具体样本 memorize 下来。 高频 bucket（1k-5k, 5k+）反而下降变慢，甚至 plateau——这些 QA pattern 的后续 token 多样性高， 模型在 train 上也很难拟合。同时，gate 机制开始激活（参考图 11.x）， n-gram table 的内容开始被注入到 attention value head 中。这一阶段 val loss 基本平稳， 因为 memorize 的规模还不够大，被通用 pattern 的收益抵消。

Val loss 按 bucket 分解。Epoch 2（step 337-686）期间，novel bucket（红）和低中频 bucket 的贡献开始缓慢上升，但被 5k+ 高频 bucket 的贡献下降所抵消——总 val loss 看起来平稳。

第三个 epoch：memorize 的全面爆发。 这是之前分析最难解释的部分，现在 hit count 数据给出了清晰答案。 两个事件在 step 686-750 之间同时发生：

  1. LR schedule 切换到 warmdown（lrm_adam 从 0.33 降到 0.05）。 学习率变小意味着模型不再"探索"新的通用 pattern，而是开始"收敛"到当前 batch 的特定样本上。 图 14.9 显示所有 bucket 的 train loss 在 step 750 同步坍塌——这是 memorize 的标志， 不是学习的标志。真正的学习是渐进的，memorize 才是突变。
  2. 低中频 bucket 的 memorize 达到临界点。 出现 6-200 次的 context，在 epoch 1-2 已经见过几次但还没完全记住， 到了 epoch 3 加上 LR 变小，模型把这些 context 的特定后续 token 全部背了下来。 但 val 中即使遇到相同的 context，后续 token 也不同，模型的"过度自信"预测反而出错。
图 14.9 特写：step 750 附近所有 bucket 的 train loss 同步坍塌。 这不是"学习 breakthrough"，而是 LR 切换引发的 memorize 突变。 同步性是关键证据——如果是学习，不同频率 bucket 应该有自己的节奏。

为什么 epoch 3 的 val 翘起比 epoch 2 显著得多？答案在图 14.8 的 gap contribution 分解中。 Epoch 2 期间，虽然低中频 bucket 已经开始 memorize（train loss 下降）， 但它们的 train loss 还没降到极低（~1-2），val loss 也只是轻微上升。 到了 epoch 3，LR 变小触发的 memorize 突变让低中频 bucket 的 train loss 降到 0.5-0.8， 与 val loss ~5 形成了 4-5 倍的巨大 gap。同时 novel bucket 的占比虽然不变（30%）， 但模型对已知 pattern 的过度自信让它在 novel context 上也更加"赌错"， novel loss 从 epoch 2 的 ~4 升到 epoch 3 的 ~5。

最终 gap 贡献排序。Novel bucket 占 34%，低中频 bucket（6-10, 21-50, 51-100, 101-200）合计占 32%， 高频 bucket 几乎不贡献。Val 翘起 = 数据本身的幂律分布（30% novel）+ 低中频 bucket 的全局 memorize。

为什么之前的分析解释不了 epoch 3？ 因为我们之前把注意力放在高频 bucket 上，认为"高频 memorize 导致 val 翘起"。 这个假设在 epoch 1-2 看起来合理（高频 bucket 的 train loss 确实在下降）， 但到了 epoch 3 就失效了——高频 bucket 的 train loss 反而 plateau， 而 val 翘起却更剧烈。只有当我们把 hit count 分得更细，并计算每个 bucket 的 gap contribution（而不是只看 per-bucket loss），才发现真正的 driver 是 低中频 bucket 和 novel context。这也解释了为什么 gap 是"全局性"的： 它不是某个特定频率区间的问题，而是模型在 LR 变小时对整个训练分布的 memorize。

一句话总结

Val 翘起的完整因果链：幂律分布（30% novel token 天然高 loss）→ LR warmdown（step 750 触发 memorize 突变）→ 低中频 bucket 的全面 memorize（train loss 坍塌到 0.5，val loss 5+）→ val loss 整体上升 1.5-2.0。 高频 bucket 是烟雾弹——它们的 QA pattern 天然可预测，不过拟合。 真正的 overfit 发生在"见过几次但没完全记住"的低中频区间。
