语法


一套策略是八个部分。顺序就是数据流向：市场和数据决定能看到什么，因子和标签决定预测什么，模型把因子变成信号，持仓把信号变成仓位，撮合把仓位变成成交，评测决定一个结果算不算数。




setting
├─ market       可交易域、调仓频率
├─ data         频率、字段、对齐方式
├─ features []  因子：每项有 kind + 参数 + 预处理
├─ label        预测目标：horizon + 变换
├─ model        因子 → 信号：类型 + 参数 + 拟合协议
├─ portfolio    信号 → 仓位：构造、风险缩放、约束
├─ execution    仓位 → 成交：撮合假设、成本模型
└─ evaluation   切分、指标、显著性检验




七个基线共用这八个部分，差别只在各部分填什么。Fama-French 的 model 是两段 OLS，DeepLOB 的 model 是五层网络；
时序动量的 model 只有一个 sign()，它的全部设计都在 portfolio.sizing 里。


做市策略的 features 是空的、label 是 null——它不预测方向，只对库存和成交强度反应。空字段本身也是信息。

为什么要写成 JSON


把策略写成结构化文本，有三件事立刻变得可做，而自然语言描述或一份 notebook 做不到。


一、两套策略的差别成了可以数的东西


Carhart 四因子相对 Fama-French 三因子，JSON 上的差别是：features 多一项动量、model.factors 多一行 UMD、model.second_stage.regressors 多一个元素。
三处改动，可以精确地说"这两套策略相距三步"。在自然语言里，这是"加了动量因子"这样一句无法比较的话。


二、一个策略族成了一个可以遍历的空间


把一套策略的 JSON 里"可以换"的字段，从一个值改成一个候选列表，就得到这一族的 schema。固定的字段原样留着，候选列表就是搜索轴。


三、评测协议和策略分开了


evaluation 是 setting 的一部分，但它独立于前七项。同一套评测协议可以套在任何一个策略上，不同策略的分数因此可比。
反过来，evaluation.split 写错——比如滚动切分没有 purge 和 embargo——整张表的分数都是假的，而这个错误在 JSON 里是看得见的一行。

元模型在做什么


输入：这张 schema + 评测协议 + 已经跑过的记录。输出：下一批最值得跑的 JSON。


给定评测协议，从空间里挑出值得跑的那个 JSON。


元模型的输入是一批候选 JSON 和已经跑过的历史记录，输出是对每个候选"在这个评测协议下会得多少分"的预测，以及一个排序。它不替代回测，它决定下一次回测该跑哪个。

第三行是关键：同一个模型，训练集里加进同类任务的历史记录，效果从 0.59 提升到 0.30。
这意味着一个团队积累的历史回测记录不是沉没成本，是可以学的资产。经典贝叶斯优化做不到这一点——它每换一个任务都从零开始。

第三件事：判断一个"赢"是不是真的


在同一场搜索里，我们还量了一件事：按单次评估排名挑出的前几名，和重复四次后的排名，秩相关是 −0.18，等于没有关系。
单次排第一的配置，重复后掉到第八；真正的第一名在单次里排第五。


这就是回测过拟合，换了个名字。在几万个因子里按一次回测挑出来的"最好"，挑到的必然是运气好的那个。
我们的做法不是事后做统计修正，而是把它写进流程：任何一个"赢"的结论，不补重复、不做配对检验，系统不让它进结论。
上面那场搜索最后的判定是"前几名和已知最好分不开"，没有宣布找到更好的，尽管单次排名上看着赢了 2%。
