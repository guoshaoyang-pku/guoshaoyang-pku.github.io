PG 小模型结构研究 · 代理模型 side project

现在的 GBDT 搜索器不差，但它给的不确定性不能用；拟合最准的是 ExtraTrees

三份已有数据（grand_1024 8,225 个设置、考试 46,066 个、重点空间 945 个），六种拟合器，离线指标、主动搜索回放和种子噪声底线。全部是这台 Mac 上的 CPU 计算，没有向集群排作业。

结论

拟合器：数据上千以后 ExtraTrees / RandomForest 最准：考试数据全量训练时前 10% 内 Spearman 0.87，已经贴着噪声上限 0.86，GBDT×8 只有 0.56；它们的 90% 区间覆盖率也接近名义值（0.85–0.96），拟合速度快一个数量级以上。只有 64 个点时 GP 的前排排序最好（重点空间 0.60，GBDT 0.09）。MLP 和 Transformer 序列模型在三份数据上都没赢过树模型。

现在的 GBDT 逐成员 argmin：当搜索器用，它是最稳的一档。考试数据回放里 20 个种子全部在 256 次评估内找到全集最优，平均 31 次进入前 1%；随机搜索要 80 次，256 次后还差 0.010；GP-EI 只有 5/20、MLP 逐成员 argmin 14/20 在 256 次内找到最优。它的毛病在模型本身：bootstrap 成员几乎一致，90% 区间的实际覆盖率随数据量从 0.72 掉到 0.15，所以同一个模型改用“均值−σ”反而更慢；数据上千后它欠拟合。反过来，离线最准的 ExtraTrees 拿来逐成员 argmin，常卡在离最优约 0.004（≈1 个种子 σ）的地方（20 个种子里只有 7 个在 256 次内找到最优）：树不会外推，8 组成员给出同一个答案。拟合准不等于搜得好。

种子噪声底线：同一设置换 seed，分数标准差的中位数是 0.0043（考试）和 0.0056（grand_1024）。grand_1024 的前 10% 只跨 0.006，完美模型对着单 seed 标签，前排 Spearman 也只能到约 0.24，所有拟合器都已到这个水平（0.2–0.4）。所以在 grand 前排继续比较拟合器没有意义，差距小于 0.005 的设置要靠多 seed 复测来分。

上限的算法：把观测分数当真值，再加一份 N(0, σ²/k) 的种子噪声（k = 该标签平均的 seed 数），算两者在前 10% 内的 Spearman：完美模型对着这些单 seed 标签，大约也就能到这个数。grand_1024 的前 10% 只跨 0.006，约等于一个种子标准差，前排排序基本由噪声决定。

做法

特征：重点空间用 focus_search.features() 原样；grand 和考试数据用同一思路的扁平化（全局项：有序数值 / 类别 one-hot；每层槽位：mixer one-hot、MLP 类型、log(1+倍率)、repeat 标记；加层数与各类计数）。GP 用同一扁平特征标准化后的 Matérn-5/2 + 白噪声，训练点超过 1,500 时随机取 1,500。Transformer 把每个全局项当一个 (路径, 取值) token、每层当一个 token（mixer + MLP 类型 + 倍率 + 位置嵌入相加），2 层 d=64，均值池化回归。标签是该设置所有 run 的均值（多数只有 seed 42 一个）。覆盖率 = 真值落在 均值 ± 1.645σ 内的比例（名义 90%），σ 来自集成成员分歧或 GP 后验。重点空间的日志在跑的过程中还在增长：离线指标用的是当时 945 个设置的快照，回放全部用之后冻结的 1,002 个设置快照（cache_focus.pkl），所有方法看到同一个候选池。脚本 tools/meta_surrogate/bakeoff.py，数据和表在 outputs/meta_surrogate/bakeoff/。

由 tools/meta_surrogate/bakeoff.py report 生成。分数是本项目协议：单张 RTX PRO 5000 训练 120 秒，最后 64 步训练 loss（nats/token，越低越好）。
